# Shared content and cross-platform fixtures

Everything in here is **generated by the iOS test suite** and consumed by the Android app. Do not
edit these files by hand.

| File | Written by | Read by |
|---|---|---|
| `assets/decks.json` | `OlaBallTests/CrossPlatformExportTests.swift` (`exportDecks`) | The Android app, as an asset, at launch (`android/app` includes this folder as an asset directory); Kotlin unit tests |
| `golden/engine.json` | `exportEngineGolden` | `android/core` tests: SplitMix64 streams, `stableHash`, bounded draws, shuffles, question draws, points and round scores |
| `golden/match-state.json` | `exportMatchState` | `android/core` tests: one `MatchState` exactly as Swift's `JSONEncoder` writes it (the wire format) |
| `golden/match-state-facts.json` | `exportMatchState` | `android/core` tests: crowns, totals, pending picks and answers Kotlin must derive from that state |

The question content itself is still authored in Swift (`OlaBall/Content/*.swift`). Running the
iOS tests regenerates `decks.json`; if the file on disk differs from what the Swift code produces,
the export test rewrites it and fails once with a message saying so. Commit the regenerated file
and the next run is green. That is the guard against a content change shipping on one platform only.

To regenerate after editing questions or rules:

```bash
xcodebuild test -project OlaBall.xcodeproj -scheme OlaBall -destination 'platform=iOS Simulator,id=22F189D4-EAEA-44E5-A62A-DFF364B638E5' -only-testing:OlaBallTests/CrossPlatformExportTests
```

Then run the Kotlin side to prove parity:

```bash
cd android && ./gradlew :core:test
```
